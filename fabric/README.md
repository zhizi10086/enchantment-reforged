# Enchantment Reforged

Minecraft **1.20.1** / Fabric 的附魔与机制改造模组：重做锋利与力量、铁砧改消耗经验点数，新增 32 个附魔（含锋利Plus）与 11 组配置页；并可选兼容矛 [Backported Spears](https://www.mcmod.cn/class/23213.html)。作者：**Summy**。

> 📖 **全附魔总表（32 个附魔的公式、目标、互斥、配置键、边界与机制附录）见 [docs/enchantments.md](../docs/enchantments.md)**

## 铁砧：消耗经验点数 + 移除"过于昂贵"

- 成本字段现在承载**经验点数**：消耗量 = 从 0 级攒到该成本等级所需的总经验（例如 30 级成本 ≈ 1395 点）。
- 点数足够才能取出（与原版"等级不足"表现一致，不会扣成负数）；创造模式不变。
- 不再有 40 级"过于昂贵"限制；界面同时显示**等级与点数**（"等级 X ／ Y 点经验"）。
- 开关：`enable_anvil_xp_cost`（关闭后完全恢复原版行为）。

## 锋利Plus 与 力量Plus

- **一个开关** `enable_custom_sharpness` 决定用哪一套：开启 = 使用锋利Plus（每级 +1.5 伤害，最高 5 级），原版锋利退出附魔台与随机战利品、两者双向互斥、暴击也放大附魔加成；关闭 = 完全恢复原版锋利。
- `enable_strength_rework`：力量改为乘算，倍率 = 1 + 0.5 × 等级（力量Plus II = 2.0 倍）；药水/信标/蘑菇煲等来源都会被重定向到力量Plus。公式：`(基础 + 锋利) × 力量 × 暴击`（下界合金剑 + 锋利Plus II + 力量Plus II + 跳劈 = 33）。
- `enable_protection_level_5`：开放原版保护 5 级（铁砧两个保护 IV → V）。

## 与「附魔描述」（Enchantment Descriptions）的兼容

`enchdesc`（mod id `enchdesc`）会在每个附魔的名字行后面**无条件**插入 `<附魔ID>.desc` 的描述文本；
两个候选键都不存在时它也不会跳过，客户端会把原始键名当文本渲染。我们的描述键一直是
`tooltip.enchantment_reforged.desc.*`，它的语言文件里也没有任何 `enchantment_reforged` 键，
所以装了它之后每个我们的附魔都会多出一行未翻译的键名。处理方式（与 Forge 版一致）：

- 为 32 个附魔补齐 `enchantment.enchantment_reforged.<name>.desc` 语言键（中英各一句话静态简介）；
- 检测到 `enchdesc` 已加载（`FabricLoader.isModLoaded("enchdesc")`）时，附魔书不再默认展开我们的
  动态数值描述，改为按住 Shift 展开（装备本来就是按住 Shift），默认只由它渲染那行简介；
- 未装 `enchdesc` 时行为完全不变。

## 与「Summy Reliquary」的近战兼容

SR 有两处自造的近战伤害（暗仪刺刀「遁入暗影」的两段斩击、投掷长矛命中），它们直接调
`player.damage(playerAttack)`，会绕过 ER 挂在 `PlayerEntity#attack` 上的近战管线。这里用一份可选兼容
把它们接回来（没装 SR 时整份配置被插件跳过，等于不存在）：

- **基础斩击 / 投掷命中**：吃全部增伤（力量 × 复仇在攻击侧、死神祝福·造成侧自 1.3.7 起在受伤侧统一结算，
  净效果与 1.3.6 相同）与全部命中后效果；
- **强力斩击**：按 SR 原设计不吃增伤乘区（1.3.7 起由"造成侧抑制窗口"显式保证：主命中与后续魔剑/斩杀**都不吃**死神祝福·造成侧），
  但吃魔剑 / 嗜血 / 粒子与**斩杀**，**不掷出其不意**；
- **SR 自己发的那条原版横扫弧线也归我们管**（1.3.4 覆盖发布起）：SR 每次斩击都会在目标身上发一条
  `SWEEP_ATTACK`，它不经过玩家左键路径、原版档位管不到，因此改为按我们的档位处置——主命中档或横扫档
  **任一 ≥1** 就不再发原版弧线（横扫档 ≥2 时在该位置生成所选横扫粒子，否则退回主命中档 ≥2）；两档都是 0
  （原版默认）时保持原版。音效不归粒子口径，照旧播放；
- **目标已死时不再掷出其不意**（1.3.4 覆盖发布起）：这一击已经把目标打死时，不再补魔剑 / 斩杀 / 出其不意，
  也不再发它们的粒子（嗜血仍按本次伤害结算，击杀照常回血），消除"只有粒子、没有伤害"的假象；
- **出其不意的粒子只在二次伤害确实落地后才播**（与左键近战同一口径）；
- **诊断日志**：`debug_sr_compat`（默认开）打开时，每次近战结算都会打一行
  `[ER-SR] strike|heavySlash|thrownSpear|melee | …`，含原始金额、乘区三分量、魔剑/嗜血/斩杀/出其不意的实际
  结果、`hurt` 返回值、目标血量与四项粒子档位——用来在实机上一眼判断某个附魔到底有没有生效（每 tick 最多 8 行、同内容去重）；
- SR 只产出 Forge 版 jar（Fabric 侧靠 Kilt / Connector 运行），`libs/summy-reliquary-1.8.5-forge.jar`
  仅作编译期依赖；由于它是 Mojang 名、与 Yarn 的继承链对不上，`build.gradle` 里额外加了
  `-AdisableTargetValidator=true`（只关闭编译期目标校验，运行期仍由 Mixin 自己校验）。

## 箭矢粒子与其它模组的箭（1.3.5）

箭矢轨迹只作用于"我们认可的箭"。判定集中在 `ArrowParticleTrails#isArrow` 一处，**客户端本地渲染与服务端
远距离代发共用同一份判定**，优先级从高到低：

1. **包含标签** `#enchantment_reforged:arrow_particles` 命中 → 一定介入（默认值 = `#minecraft:arrows` 实体标签 +
   Summy Reliquary: Apocrypha 的落箭 `summy-reliquary-apocrypha:new_testament_arrow`，两项都带 `required:false`）；
2. **排除标签** `#enchantment_reforged:no_arrow_particles` 命中 → 保持原版（整合包用它踢掉个别投掷物，例如某个模组的标枪）；
3. **原版箭 / 光灵箭** → 恒定介入（写死在代码里：联机时客户端的标签会被服务器下发的标签包覆盖）；
4. **代码内固定排除**：原版三叉戟（`TridentEntity`）与 `summy-reliquary:thrown_spear` → 不介入
   （同样写死在代码里，标签丢失也不会误伤）；
5. **其余继承箭矢基类的投掷物** → 由服务端开关 `arrow_particle_other_projectiles`（默认开）决定。

于是 Quark 火把箭、匠魂3 的箭、冰火传说的龙箭这类"继承箭矢基类、但不是原版 `Arrow`"的模组箭会自动带上轨迹；
它们本来就通过带射手的构造器/SR 的 `setOwner` 拿到了射手档位，之前只是被判定挡住了。

同一份判定还额外做了两件事：

- **档位补写（幂等）**：服务端在实体生成后的前 200 tick 内，若"这支箭还没有档位 + owner 是已登记档位的玩家"，
  就补写一次射手档位 —— 覆盖"先 `new` 出实体、之后再 `setOwner(player)`"的自定义发射路径（Fabric 树原先只认
  构造器继承，Forge 树在 `setOwner` 上打点，两边现在都兜住了）；
- **整合包可直接扩展**：往 `data/<你的数据包>/tags/entity_types/arrow_particles.json` 里加实体 id 即可让某个投掷物
  介入（可覆盖默认排除），加进 `no_arrow_particles.json` 即可让它恢复原版，改完 `/reload` 生效、不需要改代码。

**已知边界**：本机制只覆盖继承箭矢基类（`AbstractArrow` / `PersistentProjectileEntity`）的投掷物 —— 档位载体
接口就装在这个家族上。像 Iron's Spells 的 `AbstractMagicProjectile`、TaCZ 的子弹这类**自造投掷物基类**不在其中，
本次不扩到 `Projectile` 基类；原版三叉戟与已知长矛类投掷物保持"非箭类投掷物不介入"的既有口径。

## 不可闪避的伤害类型（`#enchantment_reforged:no_dodge`）

「灵动步伐」原本对所有伤害来源一视同仁地掷点（虚空、指令同样可以闪避）。现在多了一层**伤害类型标签豁免**：

- 判定点在 `EnchantmentEffects#rollNimbleSteps(LivingEntity, DamageSource)`，**第一步**就检查
  `source.isIn(#enchantment_reforged:no_dodge)` —— 命中就直接返回"未闪避"，连配置与附魔等级都不查；
- 需要"完全无法被闪避"的伤害（例如**元素伤害**这类按设定必须落地的效果）由**提供方**把自己的伤害类型
  加进 `data/<你的数据包>/tags/damage_type/no_dodge.json` 即可，`/reload` 生效、不需要改本模组代码；
- 该判断**只在伤害事件里执行一次**，命中标签时也不会播放闪避音效、不消耗任何随机数。

Summy Reliquary: Apocrypha 的 `summy-reliquary-apocrypha:apoptosis_element`（凋亡的元素伤害）就是第一个使用者。

## 伤害管线与限伤核验（1.3.7）

三条已核验的结论（代码为证，本轮只改第一条的覆盖面，其余两条只是结论）：

1. **死神祝福·受伤侧本来就是全类型**：它挂在 `LivingEntity#hurt` 的 `@ModifyVariable(argsOnly = true)` 上，
   只乘"传入的 damage 金额"，**没有任何伤害类型过滤** —— 所以箭、火、爆炸、指令伤害一律吃受伤倍率（1.3.7 未改这一侧）。
2. **死神祝福·造成侧此前只覆盖近战类**：旧实现在 `PlayerEntity#attack` 的近战与横扫、`MobEntity` 的生物近战、
   矛刺（`SpearCompat`）、SR 斩击与投掷（`SummyReliquaryCompat`）五处各自乘一次，**箭矢完全吃不到**。
   1.3.7 把这五处乘法**全部删除**，改为在受伤侧按攻击者统一结算，于是覆盖**全类型**（含箭矢），见下一节。
3. **ER 的"同 tick 多段伤害"打不过实体级 / 事件层限伤**：多段的手段是"每次 `hurt` 前清掉无敌帧
   （`timeUntilRegen = 0`）+ 再 `hurt` 一次"，而灾变（Cataclysm）/ 诡厄巫法（Goety）/ Mowzie's Mobs 那类限伤
   写在**实体本身的 `hurt` 覆写或伤害事件层**：它们在金额进入护甲 / 附魔 / 抗性之前就把值夹死，
   我们的 `bypasses_armor` / `bypasses_enchantments` 标签只作用于**原版减伤链**，因此对这类限伤**无效**。
   本模组**不尝试**绕过它们（那属于"改别人的伤害管线"，超出范围）。

**箭矢的完整伤害公式**（按实际结算顺序）：

```
基础伤害（含原版力量附魔加值）
  → × 死亡之眼 (4 + n) / 4        （n = 当前层数，上限 8）
  → × 箭速倍率（疾矢；多重射击/幻影箭的额外箭是主箭副本，继承同一数值）
  → 命中时 × 死神祝福·造成侧      （攻击者血量越低越高，1.3.7 起对箭矢也生效）
  → 目标侧：死神祝福·受伤侧 → 护盾（生命护盾/原版吸收）→ SR 等第三方拦截/限伤
```

**死神祝福·造成侧的三条边界**（新增伤害类型标签，见下）：

- **只算直接来源**：`source.getDirectEntity() == 攻击者`，或直接来源是**该攻击者拥有的投射物**（箭 / 投掷物）；
  TNT、火焰、爆炸等**间接**伤害不吃（它们的直接来源是方块/环境，不是玩家）。
- **自伤不吃造成侧**（`attacker == victim` 只吃受伤侧，例如自己射自己、跳劈）。
- **排除定值真伤**：新增标签
  `#enchantment_reforged:no_deaths_blessing_outgoing`（`data/enchantment_reforged/tags/damage_type/no_deaths_blessing_outgoing.json`，
  `replace:false` + 每项 `required:false`），默认写死 SR 的 11 个（`holy_light` / `revelation_light` / `godhead_aura` /
  `holy_light_burst` / `hellfire` / `demon_flame` / `pact_shatter` / `abyss_aura` / `golden_razor` / `sacrifice` /
  `sacrifice_self`）与 SRA 的 3 个（`apoptosis_element` / `holy_arrow` / `new_testament_arrow`）。
  整合包直接往自己的数据包同名文件里**增删**即可（`/reload` 生效，与 `no_dodge` 同风格）：把某个 id 从列表里删掉，
  那条真伤就恢复吃加成；把别人的定值真伤加进去，它就不再被放大。

## 三个箭矢附魔：轻盈 / 破空之愿 / 死亡之眼（1.3.7）

新增第 10 组配置「箭矢特性」（11 项）。三个附魔都是**服务端判定**，客户端只在轻盈的重力上参与（见下）。

| 附魔 | 效果 | 目标 / 上限 | 宝藏 |
| --- | --- | --- | --- |
| 轻盈 | 箭矢重力每级 **-25%**（3 级 -75%），总减重夹到 ≤90% 防反向重力 | 弓 + 弩 / 3 | 否 |
| 破空之愿 | 蓄力每 tick **+5%** 箭矢伤害，上限 **+200%**（40 tick 封顶；0 tick 起算） | 弓 / 1 | 是 |
| 死亡之眼 | 每次命中累计箭矢伤害 **+25% × 层数**（上限 8 层 = ×3.0）；整箭落空即清空层数 | 弓 + 弩 / 1 | 是 |

- **轻盈**：重力在 `PersistentProjectileEntity#tick` 里是**两端各自计算**的常量（0.05），所以等级必须同步给客户端，
  否则射手会看到"弹道自己回拉"。做法是新增一条 S2C 通道（实体 id + 等级，协议版本 8 → **9**），
  服务端在箭生成处向 64 格内同维度玩家广播（**先 `canSend` 判断对方装了本模组**，纯原版客户端不受影响），
  客户端写入同构表；额外箭继承等级并补发。只作用于**弓/弩射出的箭**（含其额外箭），不作用于矛或 SR 投掷物。
- **破空之愿**：在弓的生成挂点上、**生成额外箭之前**对箭的基础伤害做乘法，因此额外箭自动继承；
  倍率乘的是"基础伤害"（已含原版力量加值），会连带放大原版力量等基础项。**只作用于弓**，弩不生效；
  "真实蓄力 tick"取松手那一刻的 `useDuration - remainingUseTicks`，与速射的换算**无关**（速射只改原版威力曲线）。
- **死亡之眼**：按**射手**累计（跨武器共享）。层数 `n`（0~8）存在服务端按 UUID 的表里，
  **死亡 / 重生 / 断线即清空**。命中顺序是"**先按当前 n 算伤害，再 n+1**"：

  | 命中次数 | 1 | 2 | 3 | … | 8 | 9 及以后 |
  | --- | --- | --- | --- | --- | --- | --- |
  | 本次倍率 | ×1.00 | ×1.25 | ×1.50 | … | ×2.75 | ×3.00（封顶） |

  穿透一箭多目标时**每个目标各结算一次**（第 2/3 个目标吃更高层）。**清空只在"整箭落空"时结算（硬规则）**：
  只有这支箭**整段飞行未命中任何生物**（带参与标记但没有"已命中"标记）且已插地/被移除，才**无条件清空层数**
  （1.3.7 起固定 100%，不再掷概率）。
  **穿透命中过生物后落地一律不清空**（这是与"每支箭落地都清一次"最关键的差别，也是验收重点）；
  命中非生物实体（船 / 矿车等）算落空。
  层数被清空时会打一条节流日志（同一玩家 5 秒最多一条）：
  `[ER] 死亡之眼（玩家名）：整箭落空 → 清空（原 5 层）`。
- **两处「到顶」提示粒子**（共用开关 `arrow_trait_hint_particles`，默认开，服务端生成、附近玩家都看得到）：
  破空之愿满蓄力时在**射手身上**持续播附魔符文（`ENCHANT`，每 tick 2 个）；死亡之眼**只要层数达上限**就在
  **射手肩边**持续播附魔命中粒子（`ENCHANTED_HIT`，每 tick 2 个），与是否正在射击无关、层数清零即停。
  两者颜色与形状刻意区分（符文 vs 十字闪）。

## 原版附魔调整

- **保护 5 级**：铁砧两个保护 IV → V（`enable_protection_level_5`）。
- **穿刺改基岩版判定**：目标接触水或淋雨时生效；泡在水里又乘船时无效（`enable_impaling_bedrock_rule`）。
- **无限 + 经验修补共存**：同一件物品可以同时有这两个附魔（`enable_infinity_mending`）。
- **弓弩附魔互通**（`enable_crossbow_compat`，1.3.6 起双向）：弩可以附力量/无限/火矢/冲击并正常生效（带无限时装填不消耗箭）；
  弓可以附原版弩的**多重射击 / 穿透**并真正生效——一次射 3 支（方向按原版弩的数学、散射角读 `multishot_spread_degrees`）、
  穿透按等级真的穿透。关掉开关则两侧同时失效。
- **忠诚改版**：投掷保留本体、以"假三叉戟"代替，返回前不能再次投掷（`enable_loyalty_rework`）。

## 创造模式物品页与附魔书说明

- 新增独立物品页「Enchantment Reforged 附魔书」，里面是本模组每个附魔的满级附魔书，共 **26** 本。
- 本模组的附魔书在物品提示里会附带效果说明，**数值随配置实时变化**，并且是"该等级的总效果（每级效果）"两个数值——例如锋利Plus 的 3 级书显示"攻击伤害 +4.5（每级 +1.5）"，这样不同等级的书描述互不相同。
- 生命护盾**不再占用效果栏、也不显示图标**（1.3.1 起）：护盾值存在属性 `enchantment_reforged:life_shield` 里，可用 `/attribute @s enchantment_reforged:life_shield get` 查看；界面上只体现为原版吸收的黄心。

## 配置

共 **99 项**（开关 + 主数值 + 档位），按功能域分成 **11 组**：**核心机制 8 / 原版改动 5 / 武器附魔 12 / 弓弩与箭矢 12 / 生存与治疗 12 / 战斗状态 7 / 防御与耐久 7 / 食物与采集 7 / 粒子与特效 12 / 箭矢特性 8 / 赋能 9**。Mod Menu 图形页用顶部分类标签切换（标签一行放不下时自动分两行），一屏显示该组全部条目（不分页；窗口极矮时才启用滚轮滚动），底部是"重置全部 / 完成"。另有 2 个隐藏项（`sharpness_max_level`、`protection_max_level`）**只在配置文件里可改**，不出现在图形页与命令里。

其中 **9 项是"客户端作用域"项**（`arrow_particle`、`arrow_particle_long_distance`、`arrow_particle_distance`、`melee_particle`、`melee_sweep_particle`、`melee_particle_effect`、`surprise_particle`、`death_particle`、`nimble_steps_sound`）：服务端不会同步它们、命令里也不提供，每名玩家在自己的配置页里各选各的；射出的箭/打出的近战会把攻击者的档位带给其他人看（详见 1.2.4 / 1.2.5 / 1.2.6 / 1.3.1 各节）。

三种改法：Mod Menu 图形页、游戏内命令、直接编辑 `config/enchantment_reforged.json`。

```
/enchantmentreforged status              查看全部配置
/enchantmentreforged set <键> <值>       修改并立即保存
/enchantmentreforged reset               恢复默认
```

## 实现方式

全部只做新增注册（`Registry.register`）与定点注入，不覆盖原版注册表条目：

- 伤害管线（`PlayerEntityMixin`）：力量倍率、死神祝福造成伤害、魔剑、嗜血都在原有的伤害包装点完成。
- `LivingEntityMixin`：`damage` 参数接死神祝福受伤倍率；`heal` 接生命护盾；`setHealth` 入口做恶咒压血（避免回血红闪）；`tick` 维护生命提升/迅捷打击的属性修饰符。
- `BowItemMixin`：`onStoppedUsing` 内把 `getPullProgress` 实参按速射换算、`setVelocity` 第 5 参按疾矢放大。
- `BlockMixin`：`dropStacks` 换成熔炉产物（潜行跳过）。
- `AnvilScreenHandlerMixin` + `AnvilScreenMixin`：成本换算成经验点数、按点数判定与扣费、两处 40 级截断失效。
- `ExperienceOrbEntityMixin`：经验球给经验的那一次调用按经验学者放大。
- `EnchantmentMixin`：锋利Plus↔原版锋利、自动熔炼↔精准采集的互斥、"原版锋利退出随机池"，以及"弓弩附魔互通"（弩收弓附魔、弓收多重射击/穿透）与"无限+经验修补"的放行。
- `CrossbowItemMixin`：弩箭生成后按弩上的力量/火矢/冲击写属性，带无限时装填不耗箭。
- `BowItemMixin`：主箭生成后按弓上的穿透写原版穿透字段；带多重射击时再补左右各一支（方向按原版弩的四元数旋转、速度取主箭、散布读弓散布配置），并给三支各自按 `enable_multishot_all_hit` 决定是否"保证生效"。
- `TridentEntityMixin` + `PlayerEntityMixin`：三叉戟近战与投掷的穿刺按"接触水或淋雨"判定（替换生物类型复用原版加成）；投掷命中补上魔剑/嗜血；承载"假三叉戟"标记（飞回只消失不复制）。
- `TridentItemMixin`：忠诚改版——投掷不取走本体、给飞出去的打上假三叉戟标记、有忠诚三叉戟在飞时拒绝再次投掷。
- 事件：斩首用 `AFTER_DEATH`；本能释放用服务端/客户端 tick。
- 生命护盾（1.3.3 起）：护盾值存在玩家属性 `enchantment_reforged:life_shield` 里（1.3.1 用它取代了原来的状态效果），随玩家 NBT 持久化；`LivingEntityMixin#tick` 每 tick 只做两件事——按上限/配置/附魔等级裁剪（**只扣我方那一份**）与消耗记账，回血时只把**我方增量**加到原版吸收池上，绝不重写总量。
- 箭矢粒子：`ArrowParticleClientMixin`（客户端段）在 `PersistentProjectileEntity#tick` 上屏蔽原版暴击星并生成轨迹粒子；`PersistentProjectileEntityMixin` 把"射手档位"写进箭的原版同步字节空余高位（不新增同步字段）；`ConfigSync.PARTICLE_CHANNEL` 负责客户端上报、服务端按 UUID 记录（`ParticlePreferences`）。
- 箭矢粒子（1.2.5）：`ArrowEntityParticleClientMixin` / `SpectralArrowEntityParticleClientMixin`（客户端段）屏蔽药水箭颜色漩涡、插地消散爆发与光灵箭闪粒；`ArrowParticleTrails.tickServerTrail` 在服务端为开启远距离显示的观者逐玩家代发粒子；`ConfigSync.PARTICLE_REQUEST_CHANNEL` 是"服务端索要偏好"的通道，客户端回报 `[档位, 远距离开关, 半径]`。
- 近战粒子（1.2.6）：`MeleeParticles` 在服务端逐玩家代发；`PlayerEntityMixin` 取消原版 `addCritParticles` / `spawnSweepAttackParticles` 并在同一位置生成配置的粒子（`melee_particle` 走普通/暴击命中，`melee_sweep_particle` 走横扫）；矛左键刺击在 `SpearItemCompatMixin` 的命中点一并生成。
- 附魔台可用性（1.3.0）：不改原版随机池规则，只靠"诅咒但非宝藏"这一既有事实让恶咒 / 生命修补 / 死者之心可以被附魔；宝藏附魔不参与随机。
- 大胃袋与 HUD（1.3.0）：`HungerManagerMixin` 抬高饥饿值与饱和度上限、`HungerOwner` 让玩家侧读到本模组的上限，`InGameHudMixin`（客户端）在饥饿条上方额外画一行（满/半/空 + 金色饱和度描边，贴图内置 `textures/gui/appleskin_icons.png`）。
- 斩杀（1.3.0）：`PlayerEntityMixin` + `TridentEntityMixin` 在命中点判断目标生命 ≤ `execution_threshold` 时用自定义伤害类型 `enchantment_reforged:execution` 补刀（挂在 `minecraft:bypasses_armor` / `bypasses_enchantments` 上，攻击者仍是玩家，掉落与经验照常）。
- 防御与生存附魔（1.3.0）：`LivingEntityMixin` 负责速食、死者之心、复仇、灵动步伐；`ItemStackMixin` 承载不死者加护（主手或副手拿不死图腾时最终伤害 -`undying_grace_damage_reduction`，只生效一层、不注册状态效果，只在图腾提示里加一行）；`MobEntityMixin` 让生物侧的复仇同样成立；`DeathParticles` 负责玩家死亡粒子。
- 灵魂加护（1.3.1）：免死表现固定在服务端做（图腾音效 + 60 颗 `TOTEM_OF_UNDYING`），冷却权威是服务端计时表，`effect/SoulGraceStatusEffect` 只作可见 buff，每 20 tick 对齐一次，所以喝牛奶、`/effect clear`、死亡都绕不过冷却。
- 近战原版粒子屏蔽（1.2.6 覆盖发布）：`ClientPlayerEntityMixin` 取消本机预测的 CRIT / ENCHANTED_HIT，`ServerPlayerEntityMixin` 取消服务端向附近玩家广播的动画 4/5（这两条才是"无论怎么设置都还看得见暴击星"的原因）；受伤云 `DAMAGE_INDICATOR` 在档位 ≥1 时同点跳过。
- 闪避音效（1.3.1）：`config/DodgeSoundStyle` 定义 0–8 档，档位随 C2S `particle_style` 上报（协议 8），闪避判定发生在服务端时按**被攻击者自己的档位**在其位置播放。

## 游戏内验收

1. 铁砧 30 级操作只扣约 1395 点经验、超过 40 级仍可取、点数不足不可取、界面显示点数。
2. 经验学者只影响经验球（铁砧消耗、交易、熔炉取出经验不受影响）。

## 已知限制

- 铁砧 `cost` 字段语义变为"经验点数"（其它模组若直接读 `getLevelCost()` 可能显示差异）。
- **生命护盾与其它吸收来源是"纯加法"关系**（1.3.3 起）：护盾值自身存在属性 `enchantment_reforged:life_shield` 里（随玩家 NBT 持久化，`/attribute @s enchantment_reforged:life_shield get` 可查），写入吸收池时**只加我方增量**、消耗时**只扣我方那一份**，池子被别的模组抬高时只跟随记录、不夺权重写。因此「原版吸收 + 生命护盾 + 其它模组（例如饰品模组的魂心黄血）」稳定相加。护盾部分始终夹在「最大生命 × 20% × 等级」以内，数值量化到半颗心、上限向下取半颗心（避免 HUD 多画一颗）。1.3.2 之前这里会重写总量，可能把别人的吸收抹掉，详见对应发布记录。
- 生命护盾属性的挂载依赖玩家默认属性表：若其它模组在 `FabricDefaultAttributeRegistry` 之后也注册了玩家默认属性，会以它的为准；服务端首次 tick 会打一行自检日志（`生命护盾属性已挂到玩家默认属性：true/false`），失败时护盾安全退化、不会崩。
- 忠诚改版的"返回前不能再次投掷"按"玩家 64 格内、飞行不超过 30 秒的假三叉戟"判断，超时/飞出范围/实体消失都会立即放行，**任何情况下都不会永久无法投掷**；超过 60 秒未回收的假三叉戟会被清除（本体始终在玩家处，不构成物品损失）。
- 力量Plus 改为命中时倍率后，属性面板不再显示它带来的攻击力；其它模组用 `hasStatusEffect(StatusEffects.STRENGTH)` 判断力量将不再命中。
- 配置以服务端为准并自动同步客户端；命令需要 OP 权限等级 2。
- 箭矢粒子的"射手档位"借用原版同步字节的高位，不随存档持久化：箭被区块卸载再加载后（或跨维度后）按观者自己的设置渲染（实际飞行中的箭不受影响）。
- 箭矢粒子的远距离显示由服务端**逐玩家**代发粒子，带宽随"飞行中的箭数 × 开启该开关的玩家数"增长，因此默认关闭；半径越大覆盖越广，可调小以省带宽（上限 512 格是原版强制发粒子的硬上限，再远无法送达）。
- 近战粒子只对**玩家**的近战命中生效（主命中 + 矛左键；横扫用独立档位在身前生成），生物之间的近战不生成；横扫攻击的主目标仍会按"普通命中"档位生成一次粒子（它确实吃到一次普通伤害）。
- 启动时 Mod Menu 会报一次模组图标缺失警告（未提供图标资源，属预期）。

### 与矛 MOD（Backported Spears）的兼容

- **可附魔**：锋利Plus、魔剑、嗜血、迅捷打击都能附到矛上（附魔台、铁砧、命令均可）。

- **伤害翻倍修复**：1.4.7 的玩家分支把基础伤害算了两遍（`最终伤害 = 参数 × (1+蓄力) + 蓄力 × 附魔`）。我们在它两次攻击的 `SpearUser.pierce` 调用点上按同一公式**反解**伤害参数，使最终值正好等于"基础 + 附魔×蓄力"（右键则为它原本计算好的充能伤害），并顺带逐目标结算魔剑与嗜血。
- 伤害修正只在检测到矛模组版本为 `1.4.7` 时启用，避免对方将来修好后被我们二次修正；其它版本一律原样放行。
- **覆盖发布补丁（同一版本号）**：修掉"左键刺击不结算伤害、右键充能刺击崩服"。根因是 `@WrapOperation` 包装的 `SpearUser.pierce` 是接口调用，MixinExtras 要求把接收者作为 `Operation.call` 的第一个参数（共 7 个），此前只传了 6 个 → 每次都抛 `IncorrectArgumentCountException`（左键异常被服务端吞掉，右键异常冒泡到世界 tick）。
- **描述与链接**：`fabric.mod.json` 的描述只写内容与版本，并提示"链接见配置页"（Mod Menu 的描述框只能纯文本渲染，无法内嵌超链接）。

### 箭矢相关修正

- **弩的"无限"与弓一致**：只对普通箭免消耗（药水箭/光灵箭照常消耗），并且弩也能"无箭射出普通箭"。此前我们的弩兼容是对任何弹药都不消耗，本次修正。
- **药水箭的瞬间伤害不再被吞**（`enable_potion_arrow_full_damage`，默认开）：原版箭矢物理伤害先结算并设下 20 tick 无敌帧，紧接着施加的"瞬间伤害"会被整段免疫；现在在施加药水效果前清掉受击冷却，伤害箭与"瞬间治疗打亡灵"都能完整生效。
- **同一 tick 的多支箭都能生效**：受击冷却期内"伤害不高于上次则完全免疫"是原版规则，我们用"给箭打命令 tag、命中前清冷却"的方式处理——幻影箭的主箭与额外箭都会打标记；弩的**多重射击**由 `enable_multishot_all_hit`（默认开）控制，打开时三支打同一目标都结算。
- **疾矢可附弩**：弩射出的箭（含多重射击每支）同样吃 `×(1 + 每级加成×等级)` 的加速。
- **多重射击散射角可配置**：`multishot_spread_degrees`（默认 10 = 原版），作用于 `shootAll` 的两处 ±10°。

## 1.2.3 坚甲公式、弓散布与文案精简

- **坚甲改为按最大耐久计算**：`max(1, floor(最大耐久 × 等级系数))`，等级系数默认 **5% / 3% / 1%**（`sturdy_coefficient` 0.05 + `sturdy_coefficient_step` 0.02 递推）。参考量级：钻石胸甲（528）三级上限 26/15/5，铁靴（195）9/5/1，每件至少 1 点。附魔书显示等级系数百分比、装备显示按该件算出的具体点数。**1.2.4 起不再有"部位系数"**（原 `sturdy_slot_factor` 及其四部位拆分均已移除）。
- **弓的自然散布可配置**：新增 `bow_inaccuracy`（默认 1.0 = 原版，0 = 完全精准），改的是 `BowItem` 里 `setVelocity(...)` 的散布实参；弩不受影响（弩的散布由 `multishot_spread_degrees` 管）。
- **多支箭的"效果也生效"保险**：原版只有伤害成功才会调用 `onHit`，而药水效果正是在那里施加，所以被受击冷却免疫的第 2/3 支箭连药水效果都丢了。现在对打了标记的箭（幻影箭主箭+额外箭、开启 `enable_multishot_all_hit` 时的多重射击每支箭）在伤害被免疫时会清掉冷却重试一次，保证伤害与药水效果都落地——弩带多重射击射药水箭时三支都会生效。
- **文案精简**：生命修补改为"治疗不再回血，按 1:N 转化为这件装备的耐久"，附魔书与装备同一句；本次新增附魔的配置悬停说明统一压成一句话。

## 1.2.7 铁砧递增惩罚修复、镀层删除与新粒子特效

- **铁砧"用几次就付不起"修复（阈值封顶）**：根因是原版把两个输入的 `repairCost`（历史使用惩罚）计入成本，并在取出时用 `getNextCost(cost)=cost*2+1` 把它翻倍写回，反复用同一件物品的成本依次是 1/2/4/8/16/32… 级。现在把换算成点数时的**等级夹到上限**（`anvil_max_cost_level`，**默认 30 级 = 1395 点**，可调 1–100）：成本最多停在该上限对应的点数，不再无限增长；原版两处"过于昂贵"判定继续失效（永不拒绝），铁砧改动整体仍由**一个开关** `enable_anvil_xp_cost` 控制，关掉即完全恢复原版。
  - 注：1.2.7 首版曾尝试"直接取消历史惩罚"（包装 `ItemStack#getRepairCost` / 改写 `getNextCost`），会破坏铁砧；已回滚，改为只动我们自己的换算步骤（纯算术封顶）。

- **删除"镀层"附魔**：注册、创造物品页条目、附魔描述与两个配置项全部移除（旧存档里物品上残留的 `plating` id 会变成未知附魔并被忽略）。
- **新增被动效果"不死者加护"**：主手**或**副手持有不死图腾时，受到的最终伤害 -`undying_grace_damage_reduction`（默认 1，可配置）；**只生效一层**（双持图腾也只有 -1），放下图腾立刻失效；不注册状态效果、不显示图标，改为在**不死图腾的物品提示**里加一行说明（开关关闭时不显示）：`不死者加护：手持时受到的全伤害 -1`。
- **创造物品栏排序**：附魔书按功能重排为"锋利Plus → 近战（魔剑/斩首/嗜血/迅捷打击/出其不意）→ 远程与箭矢（疾矢/速射/本能释放/幻影箭/无尽箭袋）→ 采集与辅助（自动熔炼/经验学者）→ 生存与防护（生命提升/生命护盾/恶咒/死神祝福/生命修补/坚甲）"，共 19 本。
- **出其不意的额外粒子**：新增 `surprise_particle`（13 档，**默认 2 火焰**，客户端作用域）；触发瞬间在目标处额外爆发一次，**强度沿用 `melee_particle_effect` 三档**；0/1 档不生成。

## 1.3.2 生命护盾不再抹掉其它模组的吸收

- **现象**：装了本模组又装其它提供"伤害吸收"的模组时（例如饰品模组的魂心黄血），对方补上的吸收会在一瞬间被清成 0——表现为黄血"闪一下就没了"，而且不抵扣伤害。
- **根因**：`combat/EnchantmentEffects#tickLifeShield` 在「护盾值归零 / 胸甲没有生命护盾附魔」这条分支里，会把吸收值直接**重写成"原版吸收效果的那一份"**（`setAbsorptionAmount(vanillaAbsorption(entity))`）。本模组自己不占吸收值时，这一句等于每 tick 把别人的吸收抹掉。
- **修复**：该分支改为只回退**我方上次写入、且超出原版吸收的那一份**（`excess = max(0, 我方记账值 − 原版吸收)`），只有 `excess > 0` 时才回写，且回写值是「原版吸收 + 池子里剩下不属于我方的那部分」；**没有我方贡献时完全不碰吸收值**。
- **顺带修掉**：原版"伤害吸收"效果（金苹果黄心）之前被每 tick 顶满的副作用也一并消失。
- 本版**只改动了 `combat/EnchantmentEffects` 这一个类**；配置项（79）、语言键（各 270）、附魔（26）均未变化。产物：`enchantment-reforged-1.3.2.jar`（1.3.1 及更早保留）。

## 1.3.3 生命护盾改为增量式（只加不抢）

- **做法**：把原来的 `adjustShield`（按"原版吸收 + 我方护盾"**重写总量**）换成 `addShieldToPool`（**纯加法**：只把我方本次的增量加到吸收池上），回血累积护盾时不再重算别人的份额。
- **每 tick 的维护只剩两件事**：① 上限 / 配置 / 附魔等级变化导致我方护盾缩小时，**只从池子里扣掉缩减的那一份**；② 记账——池子比我方上次记录少了多少，就当我方护盾被消耗了多少（也就是"先扣生命护盾"），池子被第三方抬高时只跟随记录、**不夺权重写总量**。
- **结果**：总黄血 = 原版吸收 + 生命护盾 + 其它模组吸收，稳定相加、互不顶掉；例如别的模组给 40、生命护盾给 6 时池子是 46，挨 10 点伤害后是 36，其中生命护盾那一份仍然是 6。
- **语义不变的部分**：护盾值仍存在属性 `enchantment_reforged:life_shield`（随玩家 NBT 持久化）、数值量化到半颗心、上限向下取半颗心、卸下胸甲只收回我方剩余份额。
- 本版同样**只改动了 `combat/EnchantmentEffects` 这一个类**；配置项（79）、语言键（各 270）、附魔（26）均未变化。产物：`enchantment-reforged-1.3.3.jar`（1.3.2 及更早保留）。

## 1.3.4 生命修补满血生效 + 粒子归属收敛（仅对玩家）

### 生命修补：满血时也能修耐久

- **根因**：`heal` 注入里先算"实际回复量" `healed = min(治疗量, 最大生命 − 当前生命)`，满血时它是 0，于是整段逻辑在调用生命修补**之前**就 `return` 了——满血喝治疗药水一点耐久都修不到。
- **修复**：把两个口径拆开——生命护盾与恶咒联动继续用"实际回复量"，生命修补改用 `healed > 0 ? healed : 本次治疗量`。顺序与阻断语义不变（死者之心缩放 → 生命修补（修到就吞掉这次治疗）→ 生命护盾 → 恶咒）；满血且没修到任何耐久时仍照旧提前返回（**满血依然不累积护盾**）。
- 换算公式不变：每 1 点治疗量回"每级数值 × 等级"点耐久（默认 1/级），只修**带该附魔的那件**、装备满耐久时跳过、换算后不足 1 点不修。

### 粒子归属：只有玩家发起的行为才有自定义粒子

- **箭矢粒子**：`ArrowParticleRenderer#styleOf` 与 `ArrowParticleTrails#tickServerTrail` 里的"观者档位代偿"全部删除——箭上没有携带射手档位时（**生物、发射器、`/summon`、以及刚进服还没上报档位的玩家**）一律按**原版默认**处理：不生成轨迹、远距离也不代发，也不再按观者的设置屏蔽原版暴击星 / 药水箭颜色漩涡 / 光灵箭闪粒 / 插地消散爆发。
- **近战粒子**（普通/暴击、横扫、出其不意）：三个入口在"攻击者档位未知"时直接返回、不再排队，`emit` 里"按观者档位与强度渲染"的分支删除；生物近战与投掷三叉戟本来就不生成粒子（`isServerPlayerAttacker` 守卫）。
- **规则统一**：`0（原版默认）`与"未携带档位"在表现上等价——都等于本模组不介入。客户端本地的 `arrow_particle` 值从此只用于"上报给服务端"与配置页显示，不再作为本地渲染兜底；玩家进服后偏好登记的极短窗口内，其箭与近战对他人显示为原版，登记后新产生的箭 / 命中即恢复正常。
- **斩首口径（确认，未改代码）**：头颅掉落几率 = `每级 N% × 附魔等级`，只与等级和配置有关，**独立于抢夺**——全库没有任何 `Looting` 引用，头颅也不走原版掉落表（直接 `dropStack`）。

- 配置项（79）、语言键（各 270）、附魔（26）与网络协议（8）均未变化。产物：`enchantment-reforged-1.3.4.jar`（1.3.3 及更早保留）。

## 1.3.5 箭矢粒子兼容其它模组的箭（类兜底 + 双向标签 + 档位补写）

**现象**：装了其它模组后，它们的箭没有 ER 的箭矢轨迹。**根因**：判定 `ArrowParticleTrails#isArrow` 是实体类型
白名单（原版两箭 + 一个硬编码 id），而模组箭基本都 `extends AbstractArrow` 却**不是**原版 `Arrow`——
实测你装包里的 Quark `TorchArrow`、匠魂3 `ModifiableArrow`、冰火传说 `EntityDragonArrow` 全部落在名单外，
尽管它们早已把射手档位写进了箭本体。

**改动**：判定改为"包含标签 → 排除标签 → 原版两箭 → 代码内固定排除（三叉戟 / `summy-reliquary:thrown_spear`）
→ 其余继承箭矢基类的投掷物按开关"六级；新增实体标签 `#enchantment_reforged:arrow_particles`（默认含
`#minecraft:arrows` 与 SRA 落箭）与 `#enchantment_reforged:no_arrow_particles`（默认空）；新增服务端开关
`arrow_particle_other_projectiles`（默认开）；服务端增加一次**幂等档位补写**，覆盖"构造之后才 `setOwner`"的发射路径。
详细口径与整合包扩展方式见上面的专节。

**刻意不采用的方案**：用原版物品标签 `#minecraft:arrows` 做判据。虽然你装包里三个模组都登记了它，但它需要访问
`AbstractArrow#getPickupItem()`（`protected`，得再加注入），且客户端侧该字段不保证有值；同等的可配置性由我们
自己的两个实体标签提供，且不需要额外注入。

**验证**：两树 `gradlew build` 通过（Forge 侧 `verifyMixinTargets` 27 个文件全绿）；无头 `runServer` 两轮
（不装 SR / 装 deobf SR + Curios）都到 `Done`，日志出现 `Mixing PersistentProjectileEntityMixin … into PersistentProjectileEntity`，
零注入失败、零标签报错；`run/` 已清理。计数：配置项 80 → **81**（粒子与特效 10 → 11）、中英语言键各 298 → **300**、
数据文件 +2（两个标签）。产物：`enchantment-reforged-1.3.5.jar`（1.3.4 保留）。

## 1.3.6 弓弩附魔互通（弓兼容「多重射击 / 穿透」）

**目标**：让弓能附上原版弩的**多重射击 / 穿透**，而且**真的生效**。

**已核实的事实**：1.20.1 里穿透写在 `CrossbowItem#getArrow`（读 `Enchantments.PIERCING` 后调
`AbstractArrow#setPierceLevel(byte)`，该方法与原版弩的散射一样都是公开 API），多重射击写在
`CrossbowItem#performShooting`（生成 ±10°，ER 早前已把这两个常量改成配置项 `multishot_spread_degrees`），
而 `BowItem#releaseUsing` 里**完全没有任何**多重射击/穿透逻辑——"能附上"和"能生效"必须分别做。

**改动**：

- **开关共用**：复用 `enable_crossbow_compat`，语义扩为**弓弩附魔互通**（键名保留以免旧配置迁移）：开 = 弩收弓附魔 +
  弓收多重射击/穿透；关 = 两侧同时失效。配置项数量不变（81 项），只改了中英显示名与说明。
- **可用性**：扩展现有 `EnchantmentMixin#canEnchant` 那处注入，弓 + `MULTISHOT`/`PIERCING` 直接放行
  （附魔台、铁砧、命令、创造书随之生效）。两者的互斥沿用原版 `MultiShotEnchantment#checkCompatibility`（多重射击排斥穿透）。
- **多重射击（弓）**：主箭仍由原版弓逻辑射出；随后按 `Enchantments.MULTISHOT` 生成**左右各一支**，方向**逐字复刻原版弩**——
  把 `getViewVector(1.0F)` 用四元数绕 `getUpVector(1.0F)` 旋转 ±`multishot_spread_degrees`，再
  `Projectile#shoot(dirX, dirY, dirZ, 主箭速度, 弓散布)`；额外箭是主箭的副本（伤害/暴击/击退/**穿透**/着火/药水效果/粒子档位全部一致），
  速度取主箭因此**疾矢倍率自动带上**。三支是否"都能命中同一目标"沿用 `enable_multishot_all_hit`（与弩侧同口径）。
- **穿透（弓）**：按等级直接写原版穿透字段（先写再生成额外箭，额外箭靠 NBT 复制继承）；穿透行为走原版通用实现，上限 4 级不变。
- **弹药**：**刻意**保持"固定射 3 支、只消耗 1 支"（多出的两支白送），无限/无尽箭袋/创造照旧免耗；额外箭一律
  `Pickup.DISALLOWED`，防止"白送的箭"被回收刷箭。
- **额外箭归属修复**：`AbstractArrow`/`PersistentProjectileEntity` 的存档字段里**没有 owner**，此前幻影箭与
  多重射击的额外箭都没有攻击者 → 击杀不计入玩家（经验与抢夺都会丢）。现在复制后显式 `setOwner(原箭的 owner)`，
  幻影箭与额外箭的击杀都正常归功于射手。

**验证**：两树 `gradlew build` 通过（Forge 侧 `verifyMixinTargets` 27 个文件全绿）；无头 `runServer` 两轮
（不装 SR / 装 deobf SR + Curios）都到 `Done`，日志出现 `Mixing BowItemMixin … into BowItem`、`Mixing CrossbowItemMixin …`、
`Mixing EnchantmentMixin …`，零注入失败；`run/` 已清理。计数：配置项仍 **81**、中英语言键各仍 **300**（只改了两条文案）、
无新数据文件。产物：`enchantment-reforged-1.3.6.jar`（1.3.5 保留）。

## 1.3.7 死神祝福造成侧全类型 + 轻盈 / 破空之愿 / 死亡之眼（含限伤核验）

**目标**：让"造成侧增伤"覆盖**全类型**（含箭矢），并补三个箭矢附魔；同时把"ER 能不能打过各类限伤"给出书面结论。

**① 死神祝福·造成侧改为全类型（只算直接来源）**

- 实现在**受伤侧**统一结算：`LivingEntity#hurt` 的 `@ModifyVariable(argsOnly = true)` 里在原有"受伤倍率"之后，
  再按**攻击者**乘一次造成倍率（`EnchantmentEffects.deathsBlessingOutgoingApplies` 三道闸门：自伤跳过、只算直接来源、
  伤害类型不在 `#enchantment_reforged:no_deaths_blessing_outgoing` 里）。
- **删除**五处旧乘法：近战与横扫（`PlayerEntityMixin` 两处）、生物近战（`MobEntityMixin`）、矛刺（`SpearCompat`，
  那里现在只乘力量）、SR 斩击 / 投掷（`SummyReliquaryCompat#meleeMultiplier`）。**不删会重复叠加**（近战会乘两次）。
  **力量Plus 与复仇保持原地不动**（它们本来就只在近战类站点生效）；`[ER-SR]` 诊断日志相应只打印"力量 × 复仇"。
- 新增标签 `#enchantment_reforged:no_deaths_blessing_outgoing`（默认 SR 11 个 + SRA 3 个定值真伤，全部 `required:false`），
  用法见上文「伤害管线与限伤核验」。
- **SR「强力斩击」整条链路不吃造成侧**：`EnchantmentEffects` 新增"造成侧抑制窗口"（`ThreadLocal` 深度计数，
  `pushOutgoingSuppressed` / `popOutgoingSuppressed`），SR 的 `heavySlash` 注入点把主命中与随后的 `settleHit`
  （魔剑 / 斩杀补刀）**整段**包进该窗口；受伤侧注入看到窗口就跳过造成侧。这样强力斩击回到 1.3.6
  "不吃增伤乘区"的口径，而基础斩击 / 投掷 / 左键近战 / 矛刺 / 箭矢照旧各吃一层。
- 净效果：**近战 / 横扫 / 矛刺 / SR 斩击与投掷的伤害与 1.3.6 逐字一致**（只是乘法搬了位置），
  **箭矢（含弩箭、额外箭、其它模组的箭）新增吃到造成侧**；TNT / 火焰 / 爆炸等间接伤害**不吃**；自伤不吃造成侧。

**② 轻盈 `lightness`（弓 / 弩，上限 3，非宝藏）**

- 箭矢重力 ×(1 − 0.25 × 等级)，运行时总减重夹到 ≤0.9 防反向重力；重力常量在 `PersistentProjectileEntity#tick`
  里两端各自计算，因此新增 **S2C 通道**（实体 id + 等级）把等级同步到客户端：服务端在箭生成处向 64 格内同维度玩家广播
  （**先 `canSend`**，纯原版客户端不受影响），客户端写同构表；额外箭继承等级并补发；实体移除 / 断线 / 停服清表。
  配置：`enable_lightness`(开)、`lightness_gravity_reduction_per_level`(0.25)。

**③ 破空之愿 `sky_wish`（弓，上限 1，宝藏）**

- 伤害 ×(1 + min(每 tick 加成 × 真实蓄力 tick, 上限))，**0 tick 起算**：20 tick = +100%、40 tick 封顶 +200%；
  乘在**基础伤害**上（已含原版力量加值），在生成额外箭之前应用（额外箭自动继承）；**只作用于弓**，弩不生效；
  与速射的换算无关（取真实蓄力 tick）。配置：`enable_sky_wish`(开)、`sky_wish_bonus_per_tick`(0.05)、
  `sky_wish_max_bonus`(2.0)。

**④ 死亡之眼 `death_eye`（弓 / 弩，上限 1，宝藏）**

- 按射手累计层数 `n`（0~8，伤害 ×(4+n)/4）+ 连续落空计数 `m`；**先按当前 n 算伤害、命中后 n+1 且 m=0**；
  穿透一箭多目标时每个目标各结算一次。
- **硬规则**：清空只在"**整箭未命中任何生物**且已插地/被移除"时结算，且**固定 100% 清空**（删掉了原来的
  20%/30%/50% 分档概率与对应三项配置）；**穿透命中过生物后落地不清空**；命中非生物实体算落空；
  层数在死亡 / 重生 / 断线清空；清空时打一条 5 秒节流的日志便于实机验收。
  配置：`enable_death_eye`(开)、`death_eye_damage_per_stack`(0.25)、`death_eye_max_stacks`(8)。
- 实现：射出时给箭登记"参与统计"（服务端按实体网络 id 索引的表），命中生物时在箭的伤害包装点里乘算并打"已命中"标记，
  `tick` 尾部读标记结算落空（"已结算"标记防重复）。

**⑤ 两处「到顶」提示粒子（共用开关）**

- 新配置 `arrow_trait_hint_particles`（布尔，默认开，"粒子与特效"组）同时管辖两处提示，粒子一律**服务端生成**（附近玩家可见）：
  - **破空之愿**：新 mixin `ItemMixin` 注入 `Item#usageTick`（Forge 为 `onUseTick`）——原版弓没有覆盖这个方法，
    所以注入基类；方法内先排除客户端，再判断"是不是弓 + 有没有破空之愿 + 蓄力 tick ≥ ceil(上限 / 每 tick 加成)"，
    满足就每 tick 在**射手身上**播 2 个附魔符文（`ENCHANT`）；松手即停，弩不触发。
  - **死亡之眼**：挂在服务端每 tick 的玩家循环里（与 `tickInstinctiveRelease` 同处），**只要层数达上限**
    就在**射手肩边**每 tick 播 2 个附魔命中粒子（`ENCHANTED_HIT`）——状态式提示，与是否正在射击无关，层数清零即停。
  两者颜色与形状刻意区分（暗紫符文 vs 紫色十字闪），扩散也不同（0.3 vs 0.45）。

**⑥ 计数与产物**

- 配置 **81 → 90**（新增第 10 组「箭矢特性」并删掉三项落空概率、粒子与特效 11 → 12）；附魔 **26 → 29**；
  语言键中英各 **300 → 328**（一一对应）；新增数据文件 1 个（伤害类型标签）、新增 S2C 通道 1 条（轻盈）
  与一个 mixin（`ItemMixin`），既有协议版本号 8 → 9（其余三条通道语义不变）。
- 产物：`enchantment-reforged-1.3.7.jar`（1.3.6 保留）。

## 1.3.8 三个新附魔：闪身步 / 藏剑 / 电刀

**① 闪身步 `phase_step`（裤子 / 1 级 / 宝藏）**

- 效果：穿在裤子上时**完全免疫投射物伤害**——判定照搬末影人本体，只看伤害源是否落在**原版标签**
  `#minecraft:is_projectile` 里（箭、雪球、鸡蛋、投掷三叉戟、火球等都算；整合包可用数据包改这个标签）。
  喷溅药水的直击伤害不在该标签内，因此**不免疫**。
- 实现：与灵动步伐写在同一个受伤侧 HEAD 注入里，**闪身步先判**（命中时直接取消，不产生无敌帧/击退/受伤动画，
  也不消耗灵动步伐的随机数）；命中瞬间在受击者身上播 8 个末影粒子（`PORTAL`），无音效。
- 配置：`enable_phase_step`（开）。

**② 藏剑 `hidden_blade`（仅剑 / 1 级 / 宝藏）**

- 效果：未挥砍期间每 tick **+2%** 下一刀伤害，上限 **+400%**（默认 10 秒封顶）；加成作为攻击侧乘子，
  与力量、复仇同乘区：`原版伤害 × 力量 × 复仇 × (1 + 藏剑加成)`。
- 口径：**只有主手持着带该附魔的剑时才累积**（离开主手暂停但保留）；**任何近战挥砍都清空并进入 2 秒冷却**
  （含打空、砍空气），冷却期间停止累积；只作用于**主命中**（横扫不加成），SR 斩击与投掷不参与；
  死亡 / 重生 / 断线清空。满额时在持有人身上每 tick 播 2 个暴击星（`CRIT`，沿用共用开关
  `arrow_trait_hint_particles`），挥出后消失。
- 配置：`enable_hidden_blade`(开)、`hidden_blade_bonus_per_tick`(0.02)、`hidden_blade_max_bonus`(4.0)、
  `hidden_blade_cooldown_seconds`(2)。

**③ 电刀 `electric_blade`（仅剑 / 4 级 / 非宝藏）**

- 效果：玩家左键近战**主命中落地**后向附近目标**链式弹射**，段数 = 等级（最多 4 段、5 个目标）；
  每段伤害 = **攻击侧金额 × 0.8ⁿ**（依次约 ×0.8 / ×0.64 / ×0.512 / ×0.41）。
- 口径（已核验定稿）：**基数取攻击侧金额**（= 原版伤害 × 力量 × 复仇 × (1+藏剑加成)），**不含**护甲减免、
  目标受伤倍率与魔剑追加，因此**不存在"基数已含魔剑再乘一次"的平方**；弹射目标是链上没打过的活体，
  同一目标不会被算两次；每段先**清目标无敌帧**再用原版 `playerAttack` 打出；**每段各结算一次魔剑与嗜血**，
  但**不**触发斩杀、不出其不意、也不会再触发电刀；只对**玩家**生效（生物带该附魔不弹射）。
- 选目标：以上一段命中实体为圆心、半径 5 格内最近且本次链未命中过的活体（排除攻击者本人）。
- 表现与队列：段间 0.1 秒（默认 2 tick）由服务端队列 `ElectricArc` 在 `END_SERVER_TICK` 推进；沿线电火花
  （`ELECTRIC_SPARK`）+ 命中点小爆发，服务端广播；攻击者离线或找不到目标即结束。
- 配置：`enable_electric_blade`(开)、`electric_blade_radius`(5.0)、`electric_blade_damage_ratio`(0.8)、
  `electric_blade_delay_ticks`(2)。

**④ "严格只剑"与计数**

- 藏剑与电刀**严格只剑**，由两处共同保证：`SimpleEnchantment` 的"仅剑"清单（铁砧 / `/enchant` / 创造书 /
  随机战利品 / 村民附魔书）与新增的 `EnchantmentHelperMixin`（过滤附魔台候选，因为原版附魔台只按
  `EnchantmentTarget` 判定，光覆写 `isAcceptableItem` 挡不住斧头）。
- 计数：配置 **90 → 99**（新增第 11 组「赋能」9 项）；附魔 **29 → 32**（创造书同步 32 本）；
  语言键中英各 **328 → 356**；协议仍 9、无新数据文件与伤害类型；新增一个 mixin 与一个队列类（`ElectricArc`）。
- 产物：`enchantment-reforged-1.3.8.jar`（1.3.7 保留）。
